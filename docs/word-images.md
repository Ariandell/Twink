# Пошук і прив’язка картинок порціями до 200 запитів

Скрипт готує каталог зображень до актуального словника Twink. Він не змінює слова, прогрес, Firebase чи вигляд карток і не публікує словник на GitHub. Каталог — дані для наступного підключення до Android і вебверсії, а не готове оновлення APK.

## Wikimedia Commons — без ключа

Станом на 6 листопада 2026 року Pexels [призупинив видачу нових API-ключів](https://help.pexels.com/hc/en-us/articles/900004904026-How-do-I-get-an-API-key). Для нової інтеграції доступне джерело Wikimedia Commons, яке не потребує реєстрації:

```powershell
npm run images:batch -- --provider commons --input C:/Twink-private/words.xlsx --output C:/Twink-private/commons-catalog.json --queries C:/Twink-private/queries.json --limit 200
```

Скрипт послідовно виконує запити з паузою щонайменше 2,1 секунди між їх початками, локально обмежує доступ до 30 запитів на хвилину, передає ідентифікуючий User-Agent з URL проєкту та дотримується Retry-After/maxlag. Це нижче опублікованого [ліміту Wikimedia для ідентифікованого анонімного бота](https://www.mediawiki.org/wiki/Wikimedia_APIs/Rate_limits). 200 — розмір нашої порції, а не погодинний ліміт Commons.

Запит повертає до трьох растрових кандидатів; для прев’ю запитується ширина 500 px (API може округлити її до підтримуваного розміру). Підтримуються офіційні CDN upload.wikimedia.org і thumb.wikimedia.org. Зберігаються сторінка джерела, автор, ліцензія та її URL. Приймаються явний Public domain, CC0, CC BY та CC BY-SA; результати з невідомими умовами або без автора відкидаються. Повідомлення про додаткові обмеження зберігаються разом із кандидатом. Сторінка перегляду показує автора, джерело та ліцензію; ці поля потрібні й при майбутньому показі в застосунку.

Commons має інший характер пошуку, ніж фотосток: краще працюють короткі конкретні запити (`bank branch`, `apple fruit`). Скрипт шукає ключові слова в назвах файлів через `intitle`, щоб зменшити випадкові збіги з довгими описами. Для абстрактних слів і днів тижня все одно можуть траплятися невдалі збіги або порожні результати. Автоматичний кандидат завжди має `reviewed: false`. Кількість підібраних кандидатів не означає, що всі зображення перевірені за змістом. Відкладені прив’язки можуть мати `status: needs_review` і `selected: null`; їх можна повторити після уточнення запиту через `--retry-missing`.

Для різних провайдерів використовуйте різні файли каталогу. Наявний каталог Pexels не перезаписується результатами Commons. Порції продовжуються повторенням команди після завершення/відновлення ліміту; прихованого щогодинного завдання скрипт не створює.

## Pexels — для наявного ключа

Потрібні Node.js 24, залежності `web` (`npm ci`), експорт словника JSON або XLSX і ключ [Pexels API](https://www.pexels.com/api/). За документацією стандартний ліміт — **200 запитів на годину, 20 000 на місяць**. Один пошуковий запит повертає до трьох кандидатів для слова; успішний збіг не гарантований. Зображення під час пошуку не завантажуються, зберігаються URL, автор, джерело та прив’язка.

## Приватні файли

Тримайте ключ, словник і результати поза репозиторієм, наприклад у `work/word-images-private` поруч із checkout. Папки з назвою `word-images-private` також виключені з Git.

Файл `pexels.json`:

```json
{"PEXELS_API_KEY":"YOUR_PEXELS_API_KEY"}
```

Ключ читається тільки локальним скриптом, передається офіційному API в заголовку Authorization і не включається в HTML, каталог чи APK. Альтернатива файлу — змінна середовища `PEXELS_API_KEY`. Не передавайте сам ключ аргументом командного рядка.

## Підготувати запити без витрачання ліміту

У каталозі `web` виконайте (шляхи замініть на свої):

```powershell
npm run images:batch -- --provider pexels --input C:/Twink-private/words.xlsx --output C:/Twink-private/catalog.json --dry-run
```

JSON підтримує масив записів, об’єкт записів за ID та `{ "words": { ... } }`. XLSX — експорт Twink з колонками «Немецкое слово», «Перевод», «Пример 1»/«Пример 2»; підтримуються й ідіоми. Шаблон з кількома демонстраційними словами не замінює актуальний словник на 1800 слів.

Файл `catalog.json.plan.json` містить слова, переклади, приклади й пошукові запити. Типовий запит — німецьке слово без артикля та до двох іменників із контексту. Це евристика, без ШІ та без гарантії правильного значення. Для неоднозначних слів та ідіом змініть `query` на опис потрібної сцени, наприклад `park bench`, і `locale` на `en-US`. Повний контекст залишається локально; Pexels отримує тільки пошуковий запит.

## Запустити першу порцію

```powershell
npm run images:batch -- --provider pexels --input C:/Twink-private/words.xlsx --output C:/Twink-private/catalog.json --key-file C:/Twink-private/pexels.json --queries C:/Twink-private/catalog.json.plan.json --limit 200
```

План можна не передавати — скрипт створить запити автоматично. `--limit` обмежує кількість реальних API-запитів у запуску, максимум 200. Кешовані збіги не витрачають запити. Менша порція задається, наприклад, `--limit 20`.

Після відновлення погодинного ліміту повторіть **ту саму команду й той самий вихідний файл**. Вже знайдені та перевірені прив’язки пропускаються. Лічильник запитів спільний для ключа між запусками й каталогами; стандартне сховище — `~/.twink/pexels/<відбиток-ключа>`. Не запускайте окремі незалежні черги з тим самим ключем на різних комп’ютерах: загальний ліміт залишається один.

Скрипт не запускає прихованого завдання щогодини. Кожен запуск обробляє одну порцію та завершується. При локальному ліміті або HTTP 429 у підсумку є `resumeAt`, якщо відомий час відновлення. Якщо ключ паралельно використовують інші клієнти, порція може бути меншою за 200. Враховується й місячний ліміт із заголовків Pexels.

## Результат і перевірка

- `catalog.json` — каталог з окремим ключем для пари **німецьке слово + переклад**. Нові ID та повторення одного слова не створюють зайвих запитів; різні значення мають різні прив’язки.
- `catalog.json.review.html` — локальна сторінка перегляду. Картинки завантажуються ліниво як невеликі прев’ю; показано фотографа та посилання на Pexels. Можна обрати інший варіант або залишити слово без картинки. Кнопка «Зберегти каталог JSON» завантажує змінений каталог; збережіть його поверх робочого `catalog.json` перед наступною порцією.
- `catalog.json.last-run.json` — кількість запитів, збігів, пропущених записів, слів без результатів і причина зупинки. `matched` означає автоматичний вибір кандидата; `reviewed: false` не видається за підтверджений збіг.

Порожні результати також запам’ятовуються. Щоб повторити тільки їх, змініть потрібні запити у плані та додайте `--retry-missing`. Незмінені запити можуть отримати той самий кеш протягом 24 годин. Перевірені відмови «Лишити без картинки» повторно не обробляються.

Кожна відповідь і прив’язка зберігається атомарно. Ліміт списується локально **до** відправлення запиту, тому збій або тайм-аут не запускає безконтрольних повторів. Дві копії скрипту не можуть одночасно витрачати той самий бюджет або записувати один каталог. Після переривання достатньо повторити команду; вже записані результати залишаються.

## Умови Pexels

[Документація API](https://www.pexels.com/api/documentation/) вимагає помітного посилання на Pexels і рекомендує вказувати фотографа. Каталог зберігає ці дані, а сторінка перегляду їх показує. Під час підключення до застосунку їх також потрібно відображати. Офіційні [рекомендації щодо кешу](https://help.pexels.com/hc/en-us/articles/900006470063-What-steps-can-I-take-to-avoid-hitting-the-rate-limit) радять власний кеш відповідей; скрипт використовує 24 години.

## Перевірки без живого ключа

```sh
npm test
```

Тести перевіряють межу 200 запитів Pexels між запусками, відновлення після паузи, HTTP 429/401, місячний ліміт, кеш, збереження вибору, XLSX/JSON, захист секрету та HTML, атомарні записи й блокування паралельних запусків. Для Commons перевіряються робота без ключа, User-Agent, ліцензії, метадані, хвилинний ліміт і maxlag/Retry-After. Тестові відповіді не споживають реальні ліміти сервісів і не є готовими прив’язками для користувацького словника.
