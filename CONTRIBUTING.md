# Як запропонувати зміни

1. Зробіть Fork цього репозиторію у свій GitHub-профіль.
2. Створіть гілку для зміни, наприклад `fix/mobile-layout`.
3. Внесіть зміни та перевірте їх командами з README.
4. Відкрийте Pull Request у гілку `main` цього репозиторію.

Опишіть проблему, що змінилося і як це перевіряли. Для змін інтерфейсу додайте скріншоти мобільного й настільного вигляду. Зберігайте оригінальні екрани та сценарії; перед великим редизайном обговоріть його в Issue.

Для перевірок використовуйте `?demo=1`: дані цього режиму локальні та не записуються в Firebase. Не додавайте до комітів особисті ключі API, паролі, файли `.env.local`, Android-підписи та дані користувачів. Приклади налаштувань містяться у `web/.env.example`.

Зміни початкових ресурсів звіряються з `contracts/original-manifest.json`. Не оновлюйте контрольні суми лише для обходу невдалого тесту: поясніть зміну оригіналу в Pull Request. Візуальні виправлення оболонки містяться у `web/public/classic/compat-layout.css`.

Автоматична перевірка Pull Request запускає тести та вебзбірку. Зміни Flutter також перевірте локально через `flutter analyze` і `flutter test` після підготовки вебресурсів.
