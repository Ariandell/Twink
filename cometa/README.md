# Project Cometa

Окремий Rust-експеримент Twink. Контрольна стабільна версія — **Flutter 0.3.18+27** у `main` / `v0.3.18`, коміт `6fd60af97bcee06ac720f7568c0a6c1d321e2d2c`. Розробка Rust ведеться в `project-cometa`.

Головний критерій: зберегти вигляд, скло, шрифти, жести й анімації оригіналу та досягти кращої виміряної швидкості. Прибирати ефекти заради показників не вважається успішним перенесенням.

## Поточний етап: нативна графічна сцена 0.1.0

Rust керує станом і кадрами, `winit` — вікном та вводом, OpenGL ES / OpenGL і Skia — GPU-малюванням. Тут немає Flutter, WebView, HTML або JavaScript. Набір шрифтів Outfit/Roboto та контури SVG безпосередньо використовуються з контрольної версії. Цей низькорівневий шлях обрано для перевірки перспективи, фільтрів і кешування; це ще не остаточний вибір архітектури повного застосунку.

Є локальна сесія з трьома демонстраційними словами: картка 280 px, перспектива 1/1500, обертання 600 мс з cubic-bezier(.4,.2,.2,1), шість оцінок, утримання попереднього перекладу до появи наступного слова, підсумок. Працюють натискання/переривання звичайного обертання, вибір першої сторони й зменшення руху. Обидві сторони поточної та наступної карток записуються заздалегідь у кеш команд Skia. У спокої немає постійного циклу 60 кадрів/с; таймер оновлюється раз на секунду. Скло використовує справжній backdrop blur, градієнт, відблиск і обідок; це також перевірено піксельним тестом.

**Це графічний прототип, а не заміна стабільного APK.** Профіль, словник, імпорт та звук ще не підключені; відповідні іконки нижньої панелі поки є частиною еталонного компонування. Налаштування доступні верхньою та нижньою кнопками. Відсутні Firebase/Auth, збереження прогресу, DWDS, іспит, Excel, стікери/картинки й їхній жест відклеювання, світла тема та решта налаштувань. Текст прикладів і окремі відступи ще потребують візуальної звірки; повний збіг дизайну не підтверджено. Android-прототип поки орієнтований на портретний екран Pixel 6a.

## Збірка й перевірка

Перевірено з Rust 1.99.1, MSVC 14.51, Android SDK 36 / Build Tools 36.0.0 / NDK 28.2.13676358. `Cargo.lock` включено. Для Android потрібен `rustup target add aarch64-linux-android`.

```powershell
cd cometa
cargo test --release
cargo clippy --release --all-targets -- -D warnings
cargo run --release --bin cometa-preview
# Space — переворот; 1–6 — оцінки; Escape — закрити налаштування/вікно.
./tool/build-android.ps1
```

APK: `android/out/Cometa-0.1.0-native-graphics-arm64.apk`. Інший package ID `com.wordytwink.cometa` дозволяє встановити його поруч із Twink. Складання використовує локальний стандартний Android debug-підпис. Особисті словники, картинки та ключі в цей APK не входять. Нативна бібліотека має 16 KB ELF alignment; пакет вирівняний і підпис перевірено. Складання Android саме по собі не доводить роботу на фізичному телефоні.

```powershell
# Знімки тієї самої сцени через растровий Skia для звірки геометрії.
cargo run --release --bin cometa-preview -- --capture=ABSOLUTE_OUTPUT_DIRECTORY
# Короткий desktop GPU smoke test, не Android benchmark.
cargo run --release --bin cometa-preview -- --smoke --metrics=ABSOLUTE_OUTPUT_FILE.json
```

Знімки є рендерами демонстраційної сцени. GPU smoke test виконується на ПК: час від входу в `run()` до повернення першого swap не включає завантаження процесу/бібліотек ОС і не дорівнює Android TTID або готовності всього застосунку. CPU-підготовка кадру також не є повним GPU frame time. Ці показники **не можна порівнювати напряму** з ручним заміром Flutter «від 3 с на Pixel 6a».

## Наступні перевірки перед перенесенням функцій

1. Встановити цей окремий APK на Pixel 6a, підтвердити роботу GPU, торкань, життєвого циклу й скла; зняти однакові кадри Flutter/Rust з тим самим словом та розміром.
2. Звірити проміжні кадри, зворотний хід і зміну слова при оцінці, довгі приклади, жирний курсив і шрифти. Перенести відклеювання картинки окремим візуальним етапом.
3. Виміряти холодний запуск і тривалість кадрів на тому самому телефоні. Ціль експерименту — зменшити запуск і вкладатися у бюджет кадру; конкретного прискорення поки не підтверджено. Не підміняти готовність застосунку швидким показом порожньої оболонки.
4. Перенести правила навчання за `../contracts`, кеш і фонову синхронізацію. Потім словник/ввід тексту, озвучення, іспит, імпорт/експорт і решту екранів. Нативний ввід тексту, клавіатура та доступність — окрема ще не реалізована частина низькорівневого інтерфейсу.

Повторюваний початковий замір встановленого release-APK:

```powershell
./tool/measure-startup.ps1 -Package com.wordytwink.twink_android -Activity .MainActivity -Output flutter-startup.json
./tool/measure-startup.ps1 -Output cometa-startup.json
```

Скрипт робить 10 запусків із завершенням лише цільового процесу, не очищає даних. Android `am start -W TotalTime` вимірює початковий показ Activity, не повну готовність мережевих даних. Однакові дані, обліковий стан, мережу й кінцеву точку відліку потрібно фіксувати окремо. Поки в Rust лише локальна демосесія, порівняння з повним Twink лишається неповним.

Джерела API: [rust-skia](https://github.com/rust-skia/rust-skia), [winit Android](https://docs.rs/winit/latest/winit/platform/android/index.html), [Android startup metrics](https://developer.android.com/topic/performance/issues/launch-time). Шрифти та їхні ліцензії залишаються в `../android/assets/fonts`.
